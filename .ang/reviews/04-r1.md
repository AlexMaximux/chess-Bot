# Review: brief 04 (and 03-r1), round 1

Gates pass (123 tests, mypy 29 files, ruff, `gui --smoke 3`, `setup.sh`). The 03-r1 fixes and the two-game
session are good. Fix these items. Commit as `brief 04 r1: review fixes`. Add a test for every item marked (test).

1. **[High] Honest report.** The report says "Existing fixture `tests/fixtures/promotion_open.json`".
   That file does not exist. Never claim a file or result that does not exist (RULES.md). In this report,
   list what really tests promotion (the fake-based controller test). Do not create a fake "live" fixture.
   If you build a fixture by hand, name it `promotion_open_synthetic.json` and say it is synthetic.

2. **[High] `ui/app.py` calls the controller from the Tk thread.** `pause()`, `resume()`,
   `set_strength()`, `set_speed()` and `set_input_mode()` run on the Tk main thread. The controller lives on
   the worker event loop. `set_strength` calls `engine.set_profile` while the engine may be searching in
   `asyncio.to_thread`, which is a race on the Stockfish UCI pipe. Required:
   - Every UI command to the controller goes through `self._loop.call_soon_threadsafe(...)` or
     `asyncio.run_coroutine_threadsafe(...)`.
   - The engine profile change is applied by the controller **between** searches (pending value, like
     `_pending_input_mode`), never during an `analyse`.
   (test: `set_strength` during a fake search applies only after the search ends.)

3. **[Medium] The bot cannot be resumed from `ERROR`.** After an error the controller is paused, but
   `_on_toggle_pause` checks `_current_state == PAUSED`, so pressing the button calls `pause()` again.
   Add a public `is_paused` property on the controller and use it for the toggle and the button label.
   (test on the view model or the controller.)

4. **[Medium] The move style change is not applied.** `_on_style_changed` saves the config, but it never
   tells a running controller. Add `set_move_style()` (validated, applies from the next move) and call it
   thread-safely. (test)

5. **[Medium] README paths are wrong.** README lines 83 and 293-294 say `~/.config/chess-autoplayer/...`.
   The code uses `~/.chess-autoplayer/config.json`, `~/.chess-autoplayer/chrome-profile` and
   `~/.chess-autoplayer/logs`. Fix the README and list the log folder. Check every other path, command and
   flag in the README against the code, and run each command it shows.

6. **[Medium] Verification accepts the wrong move.** In `controller.py` the ply+1 branch has
   `elif not ver_state.is_our_turn: matched = True`, and the retry check accepts any `ply >= ply+1`. Both
   accept a different move that landed (for example a drop on the wrong square). Accept only when the move
   at index `game_state.ply` (move list SAN, or the python-chess move stack) equals our move. If a
   **different** move landed, emit `ErrorEvent("unexpected move landed: ...")` and pause. (tests)

7. **[Low] Reconnect cleanup.**
   - Close the old `CDPClient` when a reconnect succeeds; the GUI must also replace its stored `_cdp`.
     Simplest fix: the factory returns the new client as well, or the controller owns the client.
   - Only reconnect on `ConnectionLost`, not on a single timeout.
   - If the reconnect succeeds on the last attempt, do not go to `ERROR`. (test)

8. **[Low] Silent excepts (RULES.md rule 5).** Fix `except Exception: pass` in the controller retry path
   and in `app.py` `_on_close`: log at debug with the reason.

9. **[Low] The speed slider saves the config on every tick.** Debounce the save (for example 500 ms after the
   last change with `root.after`) and apply the value to the controller only when it changes.
