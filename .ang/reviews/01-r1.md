# Review: brief 01, round 1

Good work overall: all gates pass, isolated world and URL guard are correct. Fix these items
before starting brief 02. Commit the fixes on their own: `brief 01 r1: review fixes`.

1. **[High] `chrome/page.py:82-91` hijacks other chess.com tabs.** If the user has a chess.com tab
   on another page (for example a live game on `/play/online`), the code returns that tab (and the
   log says "Navigating" but nothing navigates). Never reuse or navigate a tab that is not already on
   an allowed URL. If no allowed tab exists, create a new tab with `Target.createTarget`. Fix the log
   message. Add tests for: allowed tab reused; only `/play/online` tab present → new tab created and the
   online tab untouched; no chess tab → new tab.

2. **[High] Our color is wrong after the user presses "Flip Board".** Orientation alone is not enough.
   - Add setting `play_as`: `"auto" | "white" | "black"` (default `"auto"`), validated, saved in config.
     `white`/`black` override everything.
   - For `auto`, investigate the live page for a signal independent of board orientation that tells
     which side the human plays against the bot (for example the bot's player box/avatar/name
     component and which colour it plays, or a data attribute on the board/game). Put it in the snapshot
     as `ourColorHint: "w" | "b" | null` and prefer it over orientation. Fall back to orientation when it is null.
   - Verify live: start a game as white, press Flip Board, run `probe`: our color must still be white.
     Save it as fixture `white_flipped_view.json` and add a test.

3. **[Medium] `reader.js:143-176` move-list scope is too wide.** `[class*="move-list"] .node` and
   `.move-list-wrapper .node` can pick up nodes from other lists or variations, and the condition on
   line 149 is always true. Read only from the `wc-simple-move-list` whose `board-id` equals the board's `id`
   (fallback: the first `wc-simple-move-list`). Only main-line plies (`.main-line-ply`) when that class is present.
   Remove the generic selectors and the dead condition.

4. **[Medium] `reader.js:198-211` game-over detection risks false positives.** `.board-modal-component` and
   `.board-dialog-component` are generic board modals and may appear for other dialogs. Keep only selectors
   proven to appear only at game end (`.game-over-modal-*`). Verify live that `gameOver` is false on the
   bot-selection screen, at game start, and mid-game, and true at the end. If you keep any generic selector,
   require game-over text inside it.

5. **[Low] `chrome/cdp.py`.** `close()` has `except Exception: pass` (rule 5): log at debug instead.
   `_listen_loop` must also catch unexpected exceptions (log error) and, when the connection ends for any
   reason, mark the client closed so later `send()` calls fail fast with `ConnectionLost` instead of timing out.
   Add a test: server drops the connection → pending command and next `send()` raise `ConnectionLost`.

6. **[Low] `__main__.py` probe.** Catch connection errors from `CDPClient.connect` with a clear message
   (no traceback). When the tab was just created or has no board yet, wait up to 10 s for the board before reading.
